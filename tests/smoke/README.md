# Smoke Tests

This directory contains smoke test specifications.

## Structure

```
tests/smoke/
├── auth/
│   └── login.spec.ts               # Example: Auth test
└── <feature-name>/
    └── <action>.spec.ts            # Your feature tests
```

## Test Pattern

### Auth Tests
Test login flow with manual cookie injection:
```typescript
import { test, expect } from "@playwright/test";
import fs from "fs";

test("should verify login", async ({ page, context }) => {
  const sessions = JSON.parse(fs.readFileSync(".auth/sessions.json", "utf-8"));
  await context.addCookies(sessions[process.env.USER_EMAIL!].cookies);
  await page.goto("/");
  await expect(page).not.toHaveURL(/\/auth\/login/);
});
```

### Feature Tests
Use global session (no login needed):
```typescript
import { test, expect } from "@playwright/test";
import { FeaturePage } from "../../pages/feature/Feature.page";

test("should perform action", async ({ page }) => {
  await page.goto("/");
  const feature = new FeaturePage(page);
  await feature.performAction();
  await expect(page).toHaveURL(/success/);
});
```

## Generated by AI

Tests are automatically generated when you:
1. Record a flow with Playwright Codegen
2. Use AI with `command/AI_MASTER_PROMPT.md`
3. AI creates test spec with assertions

## Running Tests

```bash
# Run all smoke tests
npm run smoke

# Run specific test
npx playwright test tests/smoke/feature/action.spec.ts

# Run in UI mode
npx playwright test --ui
```

## Best Practices

- **No login in feature tests** - Session loaded automatically
- **At least 2 assertions** per test
- **Use stable selectors** - Prefer data-testid
- **Avoid hard waits** - Use smart waiting
- **Test happy path only** - Smoke tests are for critical flows
